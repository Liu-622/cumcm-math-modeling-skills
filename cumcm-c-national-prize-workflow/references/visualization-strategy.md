# C 题可视化证据链

## 图表蓝图

P1 创建 `evidence/figures.json`，P3 冻结论文级蓝图，P5 生成数据图，P7 完成结构图、排版和总览审查。每图必须登记：

```json
{
  "figure_id": "fig_q2_03",
  "question": "Q2",
  "claim_ids": ["Q2-C01"],
  "claim": "评委看完应立即发现的可证伪论点",
  "role": "data|mechanism|result|validation|uncertainty|decision|overview",
  "source_files": ["data/processed/example.csv"],
  "source_sha256": {"data/processed/example.csv": "..."},
  "fields": ["field_a [unit]", "field_b [unit]"],
  "filters": "none",
  "transformations": "聚合、变换、排序及参数",
  "encoding": "x/y/color/size/line 的含义",
  "uncertainty": "区间或 none",
  "script": "code/figures/q2_03.py",
  "outputs": ["figures/fig_q2_03.pdf", "figures/fig_q2_03.png"],
  "paper_section": "问题二结果",
  "style_policy": "CUMCM_V1",
  "style_evidence": "script loads both registered style assets",
  "template_id": "仅style_policy=TEMPLATE时填写模板id",
  "status": "PLANNED"
}
```

无法写出 `claim`、没有已通过的 `claim_id`，或图不能改变读者对模型、结果、验证或决策的理解时，不进入正文。图表中的不适用约束标记为 `N/A`，未验证标记为 `UNVERIFIED`，不得以0代替。

## 图表角色

- 总览图：同时表达数据/参数流、模型升级、上下问接口和验证反馈；禁止只画 Q1→Q2 方框。
- 数据诊断：分布、异常、缺失、趋势、相关、时间/空间格局，用来证明模型动机。
- 模型解释：状态转移、变量关系、DAG、网络或决策流程；不能代替数学模型。
- 核心结果：预测带、分类性能、排名区间、决策矩阵、甘特、地图、路径或资源分配。
- 验证：实测—预测、残差、基线/消融、误差分布、小规模精确解或收敛证据。
- 不确定性与创新：策略相图、稳定域、风险前沿、敏感性热力图或误差传播。

不规定固定图数。每问根据证据需要选择；避免重复绘制同一结论。

## 论文级叙事与版式组件

借鉴优秀论文的高信息密度表达，但只迁移可验证的组织方法，不复制其配色、页数或题目专属图形。仅当能缩短读者理解路径时采用以下组件。

- **全篇技术路线图**：在问题分析或模型建立前后放置一张总览图，以“输入—处理—模型—输出—验证/反馈”串联全部子问题。每条分支须写明实际数据、模型接口和交付物；不得把目录标题重新画成装饰性流程图。
- **子问题证据组件**：一个实质性子问题通常由“最小流程图（输入、决策单元、模型、输出）+ 正式结果表 + 结果或验证图”构成。流程图不能替代变量定义、模型公式或证书，也不得与总览图重复。
- **同证据组图**：对同一模型版本、同一评价样本或同一决策场景的比较，优先组织为共享图例、色义、坐标和注释的多面板图；跨样本、跨版本或跨任务的图不得强行拼接。图注须说明模型版本、样本角色或规模、单位，以及不确定性口径。
- **决策呈现**：结论涉及推荐、分级或资源配置时，除可视化外给出可执行的决策表（对象、建议、阈值/区间、约束、风险提示）。图表展示备选方案与不确定性，不能只放最终选项。
- **表格与公式排版**：使用简洁的三线表或等效清晰表格；表头写明单位、统计口径和精度，未知或未验证结果如实标为“不适用/未验证”，不以 0 代替。保持全篇一致的标题层级、图表题注和公式编号位置，并以比赛模板为准。

正文严格限定25–28页（含参考文献、不含摘要和附录），这是用户指定的本包验收硬门，不是官方规定或获奖保证。少于25页或多于28页均不通过；按实际题量、必要推导、结果和验证分配各问篇幅。不足时只补充真实且有价值的分析，超过时删冗余并保留关键证据，不凑页、缩小页边距或隐藏页码。采用2026格式时还须满足 `../../_references/cumcm_2026_format_spec.md` 的适用条款。

## 附录与视觉可审计性

- 附录代码与支撑材料清单是正式证据：提交的每个可执行程序应完整排入附录或按赛题规定提供，代码排版可使用等宽字体、适度语法高亮和行号以便核验，但不得用截图或节选替代完整源码。
- 论文中的文件名、相对路径和材料清单必须与最终提交包一致；不出现本机绝对路径、用户名、作者元数据、临时目录或内部工作流名称。渲染后的代码页应可读，且与提交源码的版本一致。
- 图表数值、评价指标和决策表必须由已登记的原始数据或求解结果计算生成。禁止为“好看”手工硬编码论文数值、用训练集冒充测试集，或让图表与正文的阈值、特征集、样本切分、模型版本不一致。
- 对含同一实体多次观测的数据，预测性能、ROC/PR、特征解释及相关图表只能在按实体隔离的测试/验证集上作为泛化证据；否则必须明确标作探索性结果，不得据此写出泛化结论。

## 视觉系统

初始化时视觉资产复制到项目的 `support/visual-style/`。数据/统计图表优先调用 `mathmodel-figure-templates`：命中其模板 id（ROC、泰勒图、相关矩阵、云雨图、SHAP、和弦图、预测—真实边缘分布等，见 `../../mathmodel-figure-templates/references/figure-catalog.md`）时，先用该 skill 的 `--workflow --prepare` 将脚本放入 `code/figures/`，把模拟数据替换为真实结果；确认主张为 `PASS + INCLUDE` 后再用 `--workflow --confirm-real-data` 输出到 `figures/` 并登记。模板图必须记录 `style_policy=TEMPLATE`、显式 `template_id` 和配色说明，不能靠扫描脚本中的脆弱字符串证明来源。未命中模板的自绘图仍由 Matplotlib 实际加载 `cumcm.mplstyle` 和 `palette.json`，登记 `style_policy=CUMCM_V1`；流程图等非Matplotlib图登记 `EXEMPT` 和具体理由。同一张图只用一套配色，不混用两套。

自绘图语义保持一致：蓝=历史/基线，青绿=可行/推荐，橙=比较/提醒，暗红=风险/异常，紫灰=不确定性。颜色之外同时使用线型、标记或纹理，保证灰度和常见色觉缺陷下可辨。模板图由模板脚本自身保证可读性，但嵌入论文前仍按“论文级叙事与版式组件”补引出、编号图注和结果解读。

正文图优先 PDF/SVG 矢量格式，并保留高分辨率 PNG。坐标轴必须有变量与单位；图例不得遮挡数据；样本量、误差定义和区间口径按需要标明。不得使用彩虹色、伪 3D、Excel 截图、荧光色、强阴影或无法解释的装饰。

## 验收

数据验收：可回到源文件、哈希、字段、行列、筛选和脚本。统计验收：区间、样本角色、尺度、效应量和比较口径正确。表达验收：一图一主论点，caption说明展示内容，正文解释含义。版式验收：字体、单位、图例、颜色和输出尺寸一致。最终把全部图生成缩略图总览，检查配色漂移、重复表达、信息密度和缺图小问。视觉质量不得覆盖证据缺陷；主张失败时对应图自动退出正文。
