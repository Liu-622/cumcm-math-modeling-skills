# 安全政策

## 报告范围

请报告：

- 泄露的访问令牌、密钥或凭据；
- 意外提交的私人数据或本机敏感路径；
- 能够执行非预期命令、读取非目标文件或破坏数据的脚本行为；
- 依赖项中的已知高风险漏洞；
- 可能导致私有 Pro 内容被非授权公开的配置问题。

## 报告方式

不要在普通 Issue、Discussion 或 PR 评论中发布密钥、个人数据或可利用细节。请使用仓库 `Security` 页面中的私有漏洞报告或 Security Advisory；如果该功能不可用，请直接联系 `skillforCUMCM` 组织所有者。

报告中请提供：受影响版本、复现步骤、影响范围、已知缓解方式，以及是否已经发生公开泄露。

## 维护者响应

维护者应先限制暴露、轮换凭据或撤销访问，再调查 Git 历史和发行物；必要时重写历史并通知所有协作者重新克隆。普通内容错误不属于安全漏洞，应使用 Issue 模板报告。
