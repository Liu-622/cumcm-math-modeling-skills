## 拆解目标

好的拆解不是把题目按“问题一、二、三”机械分段，而是形成一个可执行的有向图：

- 节点是可独立定义输入、输出和成功判据的任务；
- 边表示数据、参数、状态、约束、决策或证据依赖；
- 每条边携带单位、时间边界、不确定性和失败回退；
- 最终所有节点共同回答原题，且没有被遗漏的闭环或隐藏假设。

## 建立问题依赖图

### 第一步：原子化任务

对每个题目问句拆成动作：描述、估计、预测、评价、解释、优化、仿真、比较、建议。若一个子问同时要求“预测并制定方案”，拆成预测节点和决策节点。

### 第二步：定义节点

```yaml
node_id: Q1a
goal: "一句可检验目标"
inputs: []
outputs: []
unknowns: []
decision_variables: []
constraints: []
method_class: "暂填问题类型，不先填具体模型"
success_criteria: []
assumptions: []
```

### 第三步：画边并标接口

仅当下游确实需要上游产物时连边。共同使用原始数据不自动形成 Q1→Q2，应从数据节点分别连到 Q1、Q2。

### 第四步：拓扑排序

先做所有无上游依赖且高信息价值的节点；再做依赖节点。若有循环，显式定义迭代和收敛，而不是假装无环。

### 第五步：做完整性检查

- 是否每个题目要求都有节点？
- 是否存在输出无人使用的装饰模型？
- 是否有下游输入无来源？
- 是否有同一量在不同节点定义不一致？
- 是否需要把上游不确定性传下去？

## 依赖边类型

| 边类型 | 含义 | 例子 | 必须携带的信息 |
|---|---|---|---|
| 数据依赖 | 下游使用清洗/特征后的数据 | 预处理 → 预测 | 字段、单位、切分、缺失规则 |
| 参数依赖 | 下游使用上游估计参数 | 参数识别 → 仿真 | 估计值、区间、相关性 |
| 状态依赖 | 前一阶段状态作为后一阶段初值 | 阶段 1 → 阶段 2 | 时间点、状态向量、误差 |
| 预测依赖 | 下游以未来量做决策 | 需求预测 → 调度 | 分布/区间/场景，不只点值 |
| 评价依赖 | 排名/得分影响资源分配 | 风险评分 → 优化 | 权重、尺度、排名稳定性 |
| 约束依赖 | 上游推断出可行域或阈值 | 容量估计 → 规划 | 置信边界、硬/软属性 |
| 决策依赖 | 前一决策改变后一系统 | 选址 → 路由 | 决策变量、可行性、成本 |
| 证据依赖 | 后续验证需要前一基线 | 基线 → 改进比较 | 相同切分、指标、预算 |
| 反馈依赖 | 下游结果反过来更新上游 | 控制 ↔ 动力学 | 迭代规则、停止条件 |

## 典型结构

### 串联：基础估计 → 主决策

```text
数据处理 → 参数/特征估计 → 预测/评价 → 优化 → 建议
```

适用：子问明确层层递进。风险：上游误差级联。必须有端到端情景。

### 分支：共同底座 → 多个独立子问

```text
数据审计 ─┬→ 描述/机理
          ├→ 预测
          └→ 评价
```

适用：多个子问共享数据但输出独立。不要人为把它们串起来；共享数据字典和假设即可。

### 汇合：多源证据 → 综合决策

```text
需求预测 ─┐
风险评价 ─┼→ 多目标/鲁棒优化
成本估计 ─┘
```

适用：决策同时受多个量驱动。检查量纲、时间口径和重复信息。

### 迭代：模型与决策相互影响

```text
状态估计 → 决策 → 系统响应 → 更新状态
     ↑__________________________|
```

适用：控制、动态规划、均衡或仿真优化。写明初值、迭代、收敛、最大轮数和无收敛回退。

### 分层：宏观约束 → 微观分配

先确定总量/区域指标，再做个体分配、路径或调度。验证上层方案在下层是否可实施；若不可实施，需反馈修正上层。

### 情景扇出：共同模型 → 多未来情景

基准/乐观/悲观或概率场景分别求解，再比较稳健策略。情景不是随意的三组数字，应来自历史、区间、专家或政策边界。

## 误差与不确定性传播

若下游输出为 `z=g(y, θ)`，而 `y` 是上游估计，至少选择一种传播方法：

- 局部线性/Delta method；
- Bootstrap 重跑整条链；
- Monte Carlo 从上游联合分布采样；
- 分位数/场景集传递；
- 区间或鲁棒集合；
- 极端边界和翻转阈值。

不要分别扰动高度相关参数而忽略联合相关。下游对上游误差不敏感时，也要用结果说明，而不是省略检查。

### 依赖强度分级

- **硬依赖**：没有上游输出，下游无法定义；上游失败则下游必须停或回退。
- **软依赖**：上游改善下游，但可用默认/外部值；需给回退。
- **解释依赖**：不改变计算，只用于解释；不能夸大为方法贡献。

## 循环、共享与并行

### 循环依赖

出现 `A → B → A` 时，选择：

1. 联立模型一次求解；
2. 固定点/交替优化，报告收敛；
3. 按时间展开成有向无环图；
4. 固定弱反馈并做敏感性。

禁止隐式手调直到结果“看起来合理”。

### 共享参数

多个子问使用同一参数时建立唯一来源。若各子问独立估计，比较一致性并说明为何允许不同。单位、时间窗口、样本范围必须一致。

### 可并行节点

无直接依赖的分析可并行：数据质量检查、机制推导、基线实现、候选案例检索。合并前核对共享假设和字段版本，避免各模块使用不同数据口径。

### 决策反馈

现实中的策略会改变未来数据分布。若用历史相关性预测政策实施后结果，必须讨论干预导致的分布变化；必要时用因果、机制或情景模型。

### 拆解说明

```markdown
基础节点：……，因为它不依赖其他估计并为……提供……。
关键路径：Q1a → Q2 → Q4，任何上游偏差会通过……传播。
并行节点：Q1b 与 Q3，共享……但无直接依赖。
反馈：Q4 的方案会改变……，因此通过……迭代/情景处理。
回退：若……不可识别，则使用……并降低结论强度。
```

### 图检索标签

案例检索优先按三层标签：

- 问题结构：串联、分支、汇合、反馈、分层、情景。
- 数据结构：时间、空间、网络、表格、图像、混合。
- 数学结构：估计→决策、多目标、反问题、动力学、随机约束。

题目关键词和题号仅作辅助。

## 案例库证据审计

现有依赖链保存在逐篇案例卡；以下规则用于持续审计明示依赖、推断依赖和误差传播。

- `[案例审计: PD-01]` 为 139 篇案例卡画子问依赖图，并标注正文明确关系与分析者推断关系。
- `[案例审计: PD-02]` 统计串联、分支、汇合、反馈和分层结构，禁止只按题面问题编号推断。
- `[案例审计: PD-03]` 核验上游结果作为下游输入时是否传递误差或区间；如未做，如实记为缺口。
- `[案例审计: PD-04]` 收集同一模型/参数跨子问复用的成功与冲突案例。
- `[案例审计: PD-05]` 比较结构相似但领域不同的案例，验证“问题结构检索”是否优于题目关键词检索。
