## 创新的定义

竞赛创新是对题目关键矛盾的**有证据改进**，不是复杂模型的同义词。一个创新点需同时包含：

> 原方案的具体缺陷 + 面向题目结构的改动 + 可测影响 + 适用边界。

若无法指出缺陷，或无法用消融/对照/稳健性验证改动，则只能称“尝试”或“扩展”，不能称有效创新。

## 创新机会诊断

从以下问题找机会，而不是先找热门算法：

1. **信息损失**：是否把时间、空间、网络、层级、异质性或不确定性压成了均值？
2. **假设失配**：线性、独立、平稳、同质、确定性等假设在哪些情景明显不成立？
3. **现实缺口**：是否遗漏容量、公平、可靠性、执行成本、政策约束、风险偏好？
4. **评价缺口**：是否只看平均误差，而忽略极端风险、校准、稳定性或实际效用？
5. **计算瓶颈**：是否有昂贵仿真、大规模组合、实时求解或参数不可辨识？
6. **表达缺口**：结论是否难以解释、无法转成行动或缺少不确定性？

先用基线暴露缺陷，再提出最小改动。不要在没有基线时凭想象“改进”。

## 六类可迁移创新

### 1. 模型结构创新

- **形式**：时变参数、分段机制、层级结构、网络/空间依赖、状态切换、约束学习。
- **准入**：残差、机制或题意显示原结构遗漏重要关系。
- **验证**：结构消融、信息准则/外测、参数解释、边界情景。
- **示例句式**：基线假定参数恒定，但数据在事件前后表现出稳定变点；因此引入两阶段参数，并用滚动外测检验是否改善。

### 2. 模型组合创新

- **形式**：预测→优化、机理→残差学习、聚类→分群预测、仿真→代理优化。
- **准入**：各模块职责互补且接口可验证。
- **验证**：逐模块消融 + 端到端指标 + 误差传播。
- **禁用**：同义模型串联、模块无下游用途。

### 3. 指标/目标创新

- **形式**：构造体现公平、风险、韧性、可达性、拥堵、解释成本的指标；从平均性能改为尾部或分布指标。
- **准入**：新指标能对应题目目标和现实单位，且不会重复已有指标。
- **验证**：与原指标相关/差异、极端案例、专家或现实一致性、权重敏感性。
- **风险**：人为拼接常数、只为改变排名。

### 4. 约束与决策创新

- **形式**：加入容量、时间窗、逻辑、可靠性、公平、预算、可操作性或鲁棒约束。
- **准入**：约束有题面、数据或合理现实依据。
- **验证**：约束活跃性、可行率、影子价格/代价、放松与收紧情景。
- **价值**：常比换更复杂求解器更能提升现实性。

### 5. 数据与特征创新

- **形式**：机制导向特征、时空聚合、图特征、滞后/滚动特征、无量纲组合、可靠外部数据。
- **准入**：预测/解释时确实可获得，并能回译为现实机制。
- **验证**：特征消融、泄漏审计、稳定性、缺失/噪声扰动。
- **禁用**：用未来结果构造特征；盲目增加外部数据但来源不可靠。

### 6. 算法与求解创新

- **形式**：问题专用编码/邻域、分解、热启动、约束修复、代理模型、并行、精确-启发式混合。
- **准入**：基础方法存在可测计算/可行性瓶颈。
- **验证**：同预算比较、运行时间分布、最优性 gap/小实例精确解、多随机种子。
- **禁用**：只更换 GA/PSO/SA 名称或调参后自称算法创新。

## 候选创新筛选

面对新题，先生成 3—5 个候选，再通过门槛筛选：

| 维度 | 问题 | 否决条件 |
|---|---|---|
| 题意相关 | 是否解决核心矛盾？ | 仅展示技术，无题目价值 |
| 新增信息 | 是否保留/引入原模型遗漏结构？ | 与已有模块重复 |
| 可验证 | 能否设计对照、消融或理论检查？ | 无法区分是否有效 |
| 数据支持 | 样本、标签、参数是否足够？ | 只能靠主观设定维持 |
| 实现风险 | 能否在时间/算力内稳定复现？ | 关键环节不可控 |
| 可解释 | 能否说明改动如何影响结果？ | 黑箱且题目要求机制/建议 |
| 论文收益 | 是否让逻辑更清楚而非更乱？ | 解释成本超过证据收益 |

建议将候选分成：

- **低风险创新**：现实约束、合理指标、验证加强、机制特征。
- **中风险创新**：结构改进、两阶段组合、鲁棒/多目标扩展。
- **高风险创新**：深度模型、新元启发式、复杂混合架构。只有数据和验证充分时启用。

## 创新证据与表述

### 证据阶梯

从弱到强：

1. 逻辑合理；
2. 个别案例表现改善；
3. 固定验证集/多情景改善；
4. 消融证明改动贡献；
5. 多数据切分、多随机种子、统计/实际显著；
6. 在分布漂移或极端情景仍稳定，并给出机制解释。

结论强度不得超过证据等级。

### 规范写法

```markdown
缺陷：基线在……假设下忽略……，残差/题意/约束显示……。
改动：引入……，其数学作用是……。
证据：在预设的……验证中，相对基线……；消融显示……。
代价：计算/数据/解释成本增加……。
边界：当……时改动不再适用，应退回……。
```

论文中的“创新点”应落到公式、约束、特征、算法或验证协议，而不是只换称谓。

## 伪创新与否决条件

- 仅使用更深网络、更多优化器或更新算法名。
- 没有基线，无法判断改动是否改善。
- 新模块使用未来数据、测试集或人工挑选最优结果。
- 新指标与旧指标高度重复，只是改变权重。
- 组合模型无法说明接口和误差传播。
- 为得到漂亮结论删去不利情景或异常样本。
- 只报告训练拟合或单次元启发式运行。
- 把常规预处理、调参或软件调用包装成理论创新。
- 结果改进极小且无实际意义，却用“显著提升”表述。

## 案例库证据审计

现有创新线索保存在逐篇案例卡；以下规则用于持续区分“作者声称”与“证据支持”。

- `[案例审计: IN-01]` 从 139 篇正文中提取作者明确声称的创新，并分别判断模型、组合、指标、约束、数据、算法类别。
- `[案例审计: IN-02]` 核对每个创新是否有基线、消融或敏感性证据；保留“声称创新”与“证据支持创新”的区别。
- `[案例审计: IN-03]` 提取跨题可迁移创新和题目专属技巧，明确不可机械复用的边界。
- `[案例审计: IN-04]` 统计现实约束/指标创新与复杂算法创新的出现和证据质量，不预设哪类更优。
- `[案例审计: IN-05]` 建立失败或收益有限的创新案例卡，防止知识库只保留成功叙事。
