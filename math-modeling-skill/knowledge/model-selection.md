## 核心原则

模型选择不是“列出越多越好”，而是给出可审计的决策链：

> 子问目标 → 数据与数学结构 → 必须满足的条件 → 候选模型 → 反证/验证 → 最简充分模型。

每个最终模型必须回答：

1. 它解决哪个关键矛盾？
2. 哪些假设让它可用？假设如何检查？
3. 为什么比基线和至少一个合理替代方案更合适？
4. 增加的复杂度带来什么可测增益？
5. 失败时退回什么方案？

## 选择流程

### 1. 写“模型无关规格”

在提模型名称前写出：决策变量、目标/响应、约束、数据形状、时间可用性、评价指标、解释需求、计算预算。

### 2. 建立基线

基线用于判断复杂模型是否真的改善：

- 预测：上一期、季节朴素、均值、线性回归。
- 评价：等权标准化、单核心指标、简单排序。
- 优化：现状方案、贪心、线性松弛或小规模枚举。
- 分类：多数类、Logistic、浅树。
- 聚类：随机/单簇对照、K-Means、层次聚类。
- 动力学：低阶差分/ODE、无交互版本。
- 仿真：确定性期望值或少量手工情景。

### 3. 生成候选族，而非同族堆叠

至少覆盖不同归纳偏置：可解释统计模型、结构化/机理模型、非线性或智能算法。只有当数据与目标允许时才生成复杂候选。

### 4. 先硬筛，再软评分

任何违反数据、约束、验证或可解释性底线的模型直接淘汰，不通过加权评分“补回来”。

### 5. 用预先声明的验证协议选择

先定切分和指标，再训练/求解。避免看到测试结果后更改指标或反复调参导致选择偏差。

### 6. 输出决策记录

记录候选、淘汰原因、验证结果、最终选择、回退方案和未解决风险；该记录应能直接转化为论文“问题分析/模型选择”内容。

## 硬筛选条件

| 检查 | 淘汰条件 | 典型修复 |
|---|---|---|
| 数据量 | 参数自由度远超有效样本且无强正则/先验 | 降维、简化、交叉验证或贝叶斯先验 |
| 时间可用性 | 训练特征在预测时不可获得 | 重建特征或改变任务定义 |
| 依赖结构 | 随机切分破坏时间/空间/组依赖 | 滚动、分组、空间阻断验证 |
| 可辨识性 | 多组参数产生近乎相同输出 | 固定参数、重参数化、补充观测 |
| 可行性 | 算法不能保证或检查硬约束 | 精确模型、修复算子、可行性投影 |
| 目标一致 | 优化目标与题意/现实价值不一致 | 重写目标，增加多目标或词典序结构 |
| 评价语义 | 指标方向/尺度/补偿规则不清 | 数据字典、无量纲化、非补偿方法 |
| 可解释需求 | 黑箱无法提供题目要求的机制或建议 | 可解释模型、SHAP/部分依赖仅作辅助 |
| 计算预算 | 无法在竞赛时间内稳定复现 | 降采样、代理模型、启发式 + 界 |
| 验证能力 | 无真值、无机制、无对照、无稳定性证据 | 重新定义证据或降低结论强度 |

## 三方案设计

三方案必须是**三个可辩护层级**，不是三个名字。

### 方案 A：经典稳妥

- 目的：保证逻辑闭环、可解释、易复现。
- 形式：最简充分模型 + 清晰假设 + 标准验证。
- 适用：样本小、时间紧、结论解释优先、复杂度无证据支撑。
- 禁止：把“简单”误写成不做验证。

### 方案 B：竞赛高分

- 目的：保留 A 的可解释骨架，并处理题目中特有的结构或约束。
- 形式：结构化改进、合理组合、参数优化、完整对比与敏感性分析。
- 进入条件：能指出 A 的具体偏差，且改进可通过实验验证。
- 禁止：只因模型更复杂就称为高分型。

### 方案 C：创新探索

- 目的：解决 A/B 仍未处理的重要矛盾，如动态权重、分布漂移、随机约束、网络依赖、个体异质性。
- 进入条件：创新与题意强相关；有消融、基线、稳健性或理论依据；实现风险可控。
- 回退：若增益不稳定或解释成本过高，回到 B，并把 C 作为扩展研究。

### 对比维度

为每个子问比较：预测/拟合能力、可行性、解释性、稳健性、数据需求、实现难度、计算预算、创新性、论文展示效果、失败风险。不要把这些维度强行平均；先满足硬门槛。

## 模型族决策表

| 结构条件 | 优先候选 | 禁用/慎用 | 替代或升级路径 |
|---|---|---|---|
| 小样本、近线性、需解释 | 线性/广义线性、灰色模型（需检验） | 深度网络、过多高阶项 | 正则化、稳健回归、Bootstrap |
| 单变量时间序列，有趋势季节 | 朴素、ETS、ARIMA | 随机切分的 ML | 加外生变量、状态空间、树模型 |
| 多变量表格，中等样本、非线性 | RF、XGBoost/LightGBM | 直接 LSTM/Transformer | 线性基线 + 树模型 + SHAP |
| 多指标客观评价 | 熵权/CRITIC + TOPSIS | 指标高度重复、权重解释不清 | PCA 去冗余、组合赋权、排序稳健性 |
| 专家偏好明确且有一致判断 | AHP/模糊评价 | 用 AHP 伪装客观数据结论 | AHP + 客观权重情景、敏感性 |
| 连续线性目标约束 | LP | 先上元启发式 | MILP（有整数变量）、鲁棒/随机 LP |
| 离散调度/选择，规模可控 | MILP/CP/DP | 无必要的遗传/粒子群 | 分解、列生成、启发式热启动 |
| 大规模组合优化或非凸黑箱 | 专用启发式、GA/SA/PSO | 只跑一次、无基线 | 小规模精确验证 + 多随机种子 |
| 路径、容量、连通 | 最短路、流、TSP/VRP | 忽略网络拓扑的普通回归 | 时变/随机网络、分解算法 |
| 传播/增长/守恒机制明确 | ODE/PDE/差分 | 只用黑箱拟合曲线 | 参数估计、状态空间、机理-数据混合 |
| 个体交互与随机事件主导 | ABM/离散事件/Monte Carlo | 用均值方程抹平关键异质性 | 代理模型 + 仿真优化 |
| 无标签、需要发现分组 | K-Means/层次/DBSCAN/GMM | 为后续排名而无解释地聚类 | 稳定性选择、外部验证、分群建模 |

更细的适用条件见 `model-library.md`；组合边界见 `model-combinations.md`；验证协议见 `validation-methods.md`。

## 评分与选择记录

### 软评分矩阵

只对通过硬筛的模型评分，建议 1—5 分。权重应反映题目要求，并做权重敏感性：

| 维度 | 建议权重范围 | 评分证据 |
|---|---:|---|
| 任务正确性/主要指标 | 0.25—0.40 | 预设测试协议 |
| 可解释与现实一致 | 0.10—0.25 | 参数含义、局部/全局解释 |
| 稳健与不确定性 | 0.10—0.25 | 扰动、情景、置信区间 |
| 实现与复现 | 0.05—0.15 | 运行时间、随机种子、依赖 |
| 创新与展示 | 0.05—0.15 | 新增问题价值、消融增益 |

不要让“创新性”权重压过任务正确性、可行性或证据质量。


## 何时停止增加复杂度

满足任一条件应停止升级：

- 外部/交叉验证增益低于实际意义阈值，而计算或解释成本显著增加。
- 复杂模型仅改善训练误差，测试、滚动或情景结果不稳定。
- 新增模块无法通过消融证明贡献。
- 复杂度来自模型名称，而非题目新增结构。
- 样本量、标签质量或参数可辨识性不支持更多自由度。
- 论文篇幅不足以解释模型、假设、求解与验证，导致逻辑链断裂。

**最低交付原则：**宁可提交一个经过严密验证的经典模型，也不提交三个无法说明为什么存在的模块。

## 案例库证据审计

现有统计与代表卡见 `corpus-analysis.md`；以下规则用于持续复核证据质量。

- `[案例审计: MS-01]` 从 139 篇案例卡统计“最终模型 vs. 可推断替代模型”的选择理由，禁止仅按模型出现次数排名。
- `[案例审计: MS-02]` 核验获奖论文是否真的包含显式基线和候选比较；若缺失，标记为论文证据缺口，不能补写作者未做的决策。
- `[案例审计: MS-03]` 归纳不同年份 A—E 题的复杂度、解释性和实现取舍；题号本身不作为模型选择依据。
- `[案例审计: MS-04]` 统计复杂模型相对经典模型是否有消融或误差增益证据。
- `[案例审计: MS-05]` 用案例页码交叉验证三方案框架是否覆盖真实高质量决策路径，并记录不适用的题型。
