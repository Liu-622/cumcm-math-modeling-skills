# case-072｜基于Soft Voting、XGBoost与系统聚类的信贷决策

## 基本信息

- 【题目】基于Soft Voting、XGBoost与系统聚类的信贷决策
- 【比赛】CUMCM
- 【年份】2020
- 【数据特点】有标签与无信贷记录两组企业；20个常规风险特征和5个疫情冲击特征，输出含二分类概率、多分类评级和连续贷款决策。
- 【使用模型】Soft Voting、Logistic、AdaBoost、GBDT、SVM、随机森林、XGBoost、系统聚类
- 【问题类型】概率集成、多类评级、无监督事件分层和贷款优化。
- 【证据边界】第 1 页摘要及第 25 页实现抽样；题名依据摘要规范化。

## 决策链

- 【核心问题】问题一提20特征，用五个异质分类器Soft Voting预测违约并规划贷款；问题二把违约概率加入特征，用XGBoost预测信誉等级；问题三用5项疫情特征系统聚类为3类，给风险乘数Q并重求规划。
- 【问题拆解方式】四维特征工程 → 五模型概率输出 → 软投票 → 违约风险 → 利润/风险/潜损多目标 → 概率增量特征+XGBoost多类评级 → 疫情5特征 → 层次聚类3群 → 解释/赋Q → 调整风险与规划。
- 【模型选择理由】软投票融合线性、核、树和集成分类器的概率，适合降低单模型偏差；XGBoost处理非线性多分类；系统聚类让突发冲击分层，不要求先验标签。
- 【关键公式】软投票概率 \(\hat p_i=\sum_m w_m\hat p_{im}\)；疫情后风险以 \(p_i^*=Q_{c(i)}p_i\) 进入多目标规划。
- 【算法】各基分类器训练并输出概率，按软投票平均/加权；以概率、信誉进入多目标规划；聚类后按组解释系统性/非系统性风险并乘到原违约风险。
- 【专家推断的替代方案】五模型同数据训练的误差高度相关，需交叉验证或stacking防泄漏；AUC高仍需概率校准；Q不应仅凭类标签主观赋值。

## 可信度与创新

- 【论文结构亮点】按子问题依赖顺序呈现：问题抽象、模型选择、算法求解、结果与验证，使前问输出自然进入后问。
- 【模型验证方法】Soft Voting报告准确率97.6%、AUC99.42%；XGBoost训练集准确率87.8%，后者不是泛化指标。抽样证据未见独立测试/校准曲线。
- 【创新点】把无监督疫情类别压缩为可进入规划的风险乘数，形成特征—类别—参数—决策链。
- 【主要局限】小样本高AUC可能受切分或泄漏影响；“训练集准确率”不足以验证评级；聚类3类与Q值敏感。

## 迁移规则

- 【可迁移经验】概率集成必须用折外预测和校准；聚类结果只有在可解释且能映射到决策参数时才有价值。
- 【不应该机械复制的部分】20/5特征、五模型组合、3类、Q值与多目标权重不可复制。
